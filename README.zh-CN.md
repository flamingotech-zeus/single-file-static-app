# 单文件静态应用构建流程

[English](README.md) | [简体中文](README.zh-CN.md)

> 把静态应用做成一个单文件，图表库内联进去 —— 离线可用，不需要构建工具链。

## 这是什么

这不是一篇讲怎么打包框架的指南。它针对的是一个很具体的场景：交付物必须是一个 HTML 文件，在一台没联网、也没装任何工具的机器上双击就能开。

这个约束排除掉了不少常规做法，也带来一组特定问题 —— 所以流程是写下来的，不是每次都重新摸一遍。

## 为什么开源

我们内部的小工具经常这么做：一个小看板、一个记录表、一个小算器。单文件这个约束来自交付环境，不是因为偏好。

它是一份构建配方，里面没有业务内容，放出来没有任何代价，还能省掉下一个人同样的一个下午。

## 能做什么

- **带占位的模板。** `src/app.html` 里留了一个标记位，构建时把图表库注进去，源码始终可改。
- **一条命令构建。** 构建那一步把库内联进去，写出 `index.html` —— 唯一需要交付的文件。
- **`file://` 下的存储坑，写下来了。** 浏览器在 `file://` 协议下对 `localStorage` 的限制，会直接打破最直观的设计思路。绕法记录在案。
- **自动验证。** 用浏览器自动化把构建产物打开，确认它真能跑，而不是假定构建成功了。
- **交付动作标准化。** 打开所在目录、把成品递到手上，是流程的一部分，不是事后补的。

## 环境要求

Python 3 · Node（可选，用于浏览器自动化验证）

## 安装

```bash
git clone https://github.com/<你的用户名>/single-file-static-app.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\single-file-static-app\` |
| macOS / Linux | `~/.workbuddy/skills/single-file-static-app/` |

没有构建步骤，重启对话即生效。

## 怎么用

说清你要什么工具：

- "做一个单文件 HTML，离线能用，带图表"
- "做一个本地记录表，双击就能开"
- "合成一个文件，资源都内联进去"

它会搭好模板、把库内联进去构建、在浏览器里验证一遍，然后交付。

## 注意与边界

1. **内联是有体积代价的。** 一个图表库会给 HTML 文件加上几百 KB。本地工具可以接受，对外页面未必。
2. **`file://` 是受限环境。** 不是所有浏览器 API 都能用。存储、fetch 和部分剪贴板操作的行为都不一样。
3. **这里验证比平时更重要。** 单文件的环节更少，所以静默失败更容易被漏掉，不是更难。
4. **不带框架。** 如果应用需要路由、状态管理或组件树，那就不该从这里起步。
